04 — Backend e Arquitetura

Modernização Laravel 13.21+ (Guia Prático)

Como aplicar as quatro melhorias arquiteturais e de performance introduzidas no Laravel 13.21.0 em sistemas legados e no labSIS-KIT.

Objetivo: Este documento demonstra a implementação prática das melhorias analisadas a partir do release Laravel 13.21.0, servindo como referência de modernização para transformar código legado verbal em padrões limpos baseados em atributos do PHP 8.5+ e novas APIs do framework.

Visão Geral das Quatro Melhorias

O Laravel 13.21.0 introduz recursos que reduzem significativamente o código boilerplate em Models, Controllers, Form Requests e manipulação de mídias. No projeto labSIS-KIT, aplicamos essas diretrizes para estabelecer um padrão ouro que pode ser facilmente replicado em projetos legados.

Recurso / Melhoria Padrão Legado (Antigo) Novo Padrão Laravel 13.21+ Benefício Principal
A. RouteKey Attribute Sobrescrever método getRouteKeyName() em cada model ou trait #[RouteKey('uuid')] no topo da classe do Model Código declarativo, limpo e sem poluição de métodos
B. Suporte a AVIF & Image Facade Bibliotecas externas pesadas ou conversão manual em lote sem fallback Image::fromUpload($file)->toAvif()->quality(80) Compressão superior de imagens (até 50% menor que WebP) com API fluente nativa
C. RequestAttribute Injection $request->attributes->get('key') dentro do corpo do controller #[RequestAttribute('key')] ?string $key direto nos parâmetros do método Desacoplamento, injeção de dependência limpa e testabilidade melhorada
D. Validação Base64 Nativa Regex customizadas ou closures complexas nos Form Requests 'payload' => ['required', 'string', 'base64'] Segurança e consistência na validação de payloads binários via API

1. Melhoria A: Modernização de Models com #[RouteKey]

Em projetos legados, a customização de chaves de roteamento do Eloquent exigia a implementação do método getRouteKeyName() no Model ou a criação de Traits complexas. Com o atributo #[RouteKey], declaramos essa intenção diretamente na definição da classe.

Como era no Legado vs. Como ficou no labSIS-KIT

❌ Padrão Legado (Boilerplate)

// app/Traits/UuidTrait.php
trait UuidTrait
{
    public function getRouteKeyName(): string
    {
        return 'uuid'; // Redundante e acoplado
    }
}

✅ Padrão Moderno (Laravel 13.21+)

// app/Models/MediaItem.php
use Illuminate\Database\Eloquent\Attributes\RouteKey;

#[RouteKey('uuid')]
class MediaItem extends Model
{
    use InteractsWithMedia, UuidTrait;
    // Sem necessidade de redefinir getRouteKeyName!
}

No labSIS-KIT, essa alteração foi aplicada de forma padronizada aos modelos MediaItem, Video, User (com chave uuid) e Organization (com chave slug). O método getRouteKeyName() foi completamente removido do UuidTrait, simplificando a manutenção.

2. Melhoria B: Suporte a AVIF via Image Facade e MediaService

O formato AVIF oferece uma taxa de compressão substancialmente melhor que JPEG, PNG ou WebP, mantendo a fidelidade visual. O Laravel 13.21 introduziu integração aprimorada no facade Image para conversão fluente no momento do upload.

Implementação em Serviço de Mídia (MediaService.php)

Em sistemas de gestão de arquivos (como o integrado ao Spatie Media Library no nosso starter kit), implementamos a conversão automática de qualquer upload de imagem para .avif, com tratamento de resiliência e fallback caso o driver de imagem do servidor apresente limitações:

// app/Services/MediaService.php
use Illuminate\Support\Facades\Image;
use Illuminate\Http\UploadedFile;

protected function attachUploadedFile(MediaItem $item, UploadedFile $file, string $collection): void
{
    $mime = $file->getMimeType();

    // Se for imagem e não for SVG, GIF animado ou já AVIF, converte automaticamente
    if (str_starts_with($mime, 'image/') && ! in_array($mime, ['image/svg+xml', 'image/gif', 'image/avif'], true)) {
        try {
            $avifImage = Image::fromUpload($file)->toAvif()->quality(80);
            $filename = pathinfo($file->getClientOriginalName(), PATHINFO_FILENAME) . '.avif';

            $item->addMediaFromString($avifImage->toBytes())
                ->usingFileName($filename)
                ->toMediaCollection($collection);

            return;
        } catch (\Throwable $e) {
            // Fallback resiliente para o arquivo original em caso de falha no driver
        }
    }

    $item->addMedia($file)->toMediaCollection($collection);
}

Dica de Performance: Definir a qualidade como 80 na chamada ->quality(80) representa o ponto ótimo para a maioria das aplicações web, gerando arquivos de proporção ínfima com zero perda perceptível de nitidez em telas Retina/4K.

3. Melhoria C: Injeção de Contexto com #[RequestAttribute]

Aplicações modernas em arquiteturas Multi-Tenant ou com APIs móveis utilizam Middlewares para interceptar tokens, headers (como X-Tenant-ID ou X-Client-ID) e injetá-los na requisição via $request->attributes->set('key', $value).

No padrão legado, o Controller precisava extrair manualmente esses atributos. No Laravel 13.21+, utilizamos o atributo do container #[RequestAttribute] diretamente na assinatura do método do Controller.

Fluxo de Arquitetura Limpa

  1. Middleware de Contexto (InjectRequestContext.php): Intercepta a requisição e popula os atributos.
  2. Controller (MediaUploadController.php): Recebe os valores injetados como parâmetros tipados.
// 1. Middleware populando atributos
class InjectRequestContext
{
    public function handle(Request $request, Closure $next): Response
    {
        if ($tenantId = $request->header('X-Tenant-ID') ?: $request->query('tenant_id')) {
            $request->attributes->set('tenant_id', (string) $tenantId);
        }
        return $next($request);
    }
}

// 2. Controller consumindo de forma limpa e tipada
use Illuminate\Container\Attributes\RequestAttribute;

class MediaUploadController
{
    public function store(
        StoreMediaBase64Request $request,
        #[RequestAttribute('tenant_id')] ?string $tenantId = null,
        #[RequestAttribute('client_id')] ?string $clientId = null
    ): JsonResponse {
        // O Laravel resolve e injeta automaticamente $tenantId sem acoplamento a $request->attributes!
        // ... lógica de upload ...
    }
}

4. Melhoria D: Validação Nativa base64 em Form Requests

A recepção de mídias ou documentos codificados em Base64 via APIs JSON é comum em integrações mobile e webhooks. O Laravel 13.21+ elimina a necessidade de validações customizadas, oferecendo a regra nativa base64 no motor de validação.

Aplicação no StoreMediaBase64Request.php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class StoreMediaBase64Request extends FormRequest
{
    public function authorize(): bool
    {
        return true;
    }

    public function rules(): array
    {
        return [
            'name' => ['required', 'string', 'max:255'],
            'payload' => ['required', 'string', 'base64'], // Regra nativa do Laravel 13.21+
            'mime_type' => ['nullable', 'string', 'in:image/png,image/jpeg,image/webp,image/avif'],
        ];
    }
}

5. Guia Passo a Passo para Aplicação em Projetos Legados

Para aplicar este pacote de modernizações em um sistema Laravel legado sem causar interrupções, siga esta ordem de execução recomendada:

  1. Auditoria e Atualização de Dependências

    Verifique o arquivo composer.json e garanta que o framework esteja na versão mínimo 13.21.0 (ou superior). Instale também o driver de processamento de imagens: composer require intervention/image.

  2. Substituição Gradual de getRouteKeyName()

    Faça uma busca no projeto por function getRouteKeyName. Para cada Model localizado, importe use Illuminate\Database\Eloquent\Attributes\RouteKey;, adicione a anotação no topo da classe e remova o método interno. Execute a suíte de testes de integração para validar o roteamento.

  3. Otimização de Storage e Imagens

    Identifique os pontos onde UploadedFile::store() ou manipulações manuais ocorrem. Substitua por chamadas ao facade Image::fromUpload(), garantindo um bloco try/catch ao redor para que servidores de homologação ou locais sem bibliotecas gráficas avançadas não quebrem o fluxo.

  4. Refatoração de Middlewares e Controllers de API

    Em pontos onde sua aplicação lê headers customizados ou dados de sessão temporários via $request->attributes->get(), refatore a assinatura dos métodos dos controllers para adotar #[RequestAttribute('nome_do_atributo')].

  5. Limpeza de Form Requests

    Substitua regras legadas como regex:/^[a-zA-Z0-9\/\r\n+]*={0,2}$/ pelo simples e direto 'base64'.
