03 — UI e Customização

Arquitetura e Organização das Views (Público vs. Painéis)

Este documento estabelece a convenção arquitetural da pasta resources/views no labSIS-KIT. A organização segue uma separação estrita de escopo entre a área pública do visitante e os painéis administrativos de controle, adotando a filosofia de co-localização de componentes e uso do Filament v5 standalone na área pública.

1. Princípio da Segregação de Responsabilidade

Para eliminar qualquer ambiguidade entre interfaces abertas ao público e telas internas do back-office, a raiz de resources/views/ é segregada em dois pilares fundamentais:

  1. resources/views/public/: Tudo o que pertence à experiência do visitante e usuário externo (landing page, componentes visuais da vitrine, páginas informativas abertas).
  2. resources/views/panels/: Tudo o que pertence à customização, extensão e estrutura dos painéis de controle Filament (Admin, Usuário, Autenticação).

Arquivos de e-mails transacionais residem em resources/views/mail/ e templates publicados de pacotes terceiros em resources/views/vendor/.

2. Área Pública e a Filosofia Filament v5 (resources/views/public/)

A área pública não é um site estático desconectado. Ela integra o ecossistema Livewire 4 + Filament v5, aproveitando toda a robustez de ações, formulários com validação e notificações do Filament diretamente na vitrine.

A Tríade de Páginas Livewire

Cada página pública reside em um subdiretório dentro de resources/views/public/pages/ utilizando o padrão de co-localização de arquivos (Tríade):

  • home.php: Classe anônima Livewire (new class extends Component implements HasActions, HasSchemas). Contém a lógica da página, consultas de dados (#[Computed]) e as Filament Actions (botões de ação com modais, formulários de contato, etc.).
  • home.blade.php: Template integrador da página. Renderiza a composição dos componentes Blade e inclui <x-filament-actions::modals /> para exibir os modais de ações.
  • home.js: Scripts dedicados àquela página (mantendo scripts locais isolados sem poluir o bundle global).

Roteamento Declarativo

No arquivo routes/web.php, as rotas públicas utilizam o roteamento direto do Livewire através do namespace configurado em config/livewire.php:

routes/web.php
Route::livewire('/', 'pages::home')->name('home');

Em config/livewire.php, os namespaces apontam diretamente para a pasta pública:

config/livewire.php
'component_namespaces' => [
    'layouts' => resource_path('views/public/layouts'),
    'pages' => resource_path('views/public/pages'),
],
'component_layout' => 'layouts::app',

Componentes Blade Semânticos

Os blocos visuais da área pública estão organizados por domínio em resources/views/public/components/landing/:

  • header.blade.php
  • hero.blade.php
  • diferenciais.blade.php
  • projetos.blade.php
  • ecossistema.blade.php
  • stats.blade.php
  • cta.blade.php
  • footer.blade.php

Registrados via AppServiceProvider com o prefixo public, eles podem ser invocados com clareza semântica:

blade
<x-public::landing.hero />
<x-public::landing.stats :totalProjects="$this->totalProjects" />
<x-public::landing.cta />

CSS Standalone do Filament v5

No arquivo resources/css/app.css, os estilos públicos importam os componentes standalone do Filament v5 para permitir modais, repeaters, campos de formulário e notificações estilizados pelo Tailwind:

resources/css/app.css
@import "tailwindcss";

/* Standalone Filament v5 Styles */
@import '../../vendor/filament/support/resources/css/index.css';
@import '../../vendor/filament/actions/resources/css/index.css';
@import '../../vendor/filament/forms/resources/css/index.css';
@import '../../vendor/filament/infolists/resources/css/index.css';
@import '../../vendor/filament/notifications/resources/css/index.css';
@import '../../vendor/filament/schemas/resources/css/index.css';

3. Área dos Painéis (resources/views/panels/)

Tudo o que estende, sobrescreve ou implementa interfaces nos painéis Filament (Admin, User, Auth) reside centralizado nesta pasta.

Subdiretório Finalidade Exemplo no Código PHP
panels/auth/ Logos e telas de autenticação dos painéis view('panels.auth.logo_auth')
panels/clusters/ Páginas de clusters e permissões $view = 'panels.clusters.permissions.pages.users-permissions';
panels/components/ Componentes de navegação e layout dos painéis view('panels.components.mobile-bottom-nav')
panels/forms/ Campos e previews customizados para Schemas de formulário ->view('panels.forms.components.video-preview')
panels/livewire/ Componentes Livewire internos dos painéis (Central de Notificações) return view('panels.livewire.notification-center');
panels/pages/ Páginas personalizadas do painel (ex: aceite de convite, verificação) $view = 'panels.pages.accept-invite';
panels/resources/ Telas dedicadas de Resources (ex: confirmações de exclusão) return 'panels.resources.users.pages.delete-user';

5. Guia Rápido para Desenvolvedores

Onde crio uma nova página pública?

Crie um diretório sob resources/views/public/pages/<nome-da-pagina>/ contendo a tríade <nome>.php e <nome>.blade.php. Em seguida, registre no routes/web.php:

routes/web.php
Route::livewire('/sobre', 'pages::sobre')->name('sobre');

Onde crio um componente reutilizável para a área pública?

Adicione o arquivo Blade em resources/views/public/components/landing/<componente>.blade.php e utilize a tag:

blade
<x-public::landing.<componente> />

Onde crio uma view para um Resource ou Page do Filament?

Adicione sempre dentro de resources/views/panels/ na respectiva subpasta (pages/, resources/ ou forms/). No PHP, referencie usando a notação panels.<caminho> (ex: panels.resources.produtos.pages.detalhes).
